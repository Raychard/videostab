## 1. TL;DR

- **DUT（2020/2022）是无监督网格轨迹防抖的开山之作**：首次证明只用不稳定视频（无需稳定/不稳定成对数据）就能训练防抖网络，把经典"关键点 → 网格轨迹 → 平滑"管线中每一步换成可微模块，用空间/时间一致性作为自监督信号。
- **NLNL（2026）可以看作 DUT 思想的"在线化 + 工程化"直系后继**：同样是无监督、同样是网格轨迹框架、损失函数几乎同源（关键点一致性 + 单应投影 + 网格正交保形 + 时域平滑），但把 DUT 的三个落地短板逐一补掉——**离线改在线（零未来帧）、脆弱的单一运动估计器改多检测器协同、全局双向平滑改因果动态核**，并用三线程流水线在 Jetson AGX Orin 上跑到 ~12.7 FPS。
- 一句话总结差异：**DUT 回答"无监督防抖能不能做"，NLNL 回答"无监督防抖能不能上机跑"**。若做嵌入式/无人机/在线防抖，NLNL 的架构是当前纯视觉路线里落地参考价值最高的设计之一；若做离线后期且允许逐段调参，DUT 家族画质仍有竞争力。

## 2. DUT 算法详细解读

### 2.1 背景与定位

2018 年的 StabNet 证明了 CNN 可以端到端防抖，但依赖 DeepStab 这类"手持相机 + 稳定器同步拍摄"的成对数据——采集成本高、场景覆盖窄、泛化差。DUT 的核心命题是：**经典防抖管线（运动估计 → 轨迹平滑 → 重投影）中的监督信号其实蕴含在不稳定视频自身的时空一致性里**，因此可以把管线每一步神经化后无监督训练，"只看不稳定视频就学会防抖"。

### 2.2 总体流程

```
输入帧对 ──► ①运动估计            ──► ②运动传播（稀疏→稠密网格） ──► ③轨迹平滑 ──► ④网格重投影渲染
            RFNet 关键点              多单应初始化                    3D CNN 预测
            + PWC-Net 光流            + 残差细化网络                  动态平滑核
```

**① 运动估计**：RFNet 检测 L=512 个关键点，PWC-Net 估计相邻帧稠密光流，在关键点处采样得到稀疏但可靠的运动向量。

**② 运动传播（稀疏 → 稠密网格）**，分两步：
- **多单应初始化**：对关键点运动做 K-means 聚成两类（近似前/后两个平面），每类分别用 RANSAC 估计单应 H；每个网格顶点按半径 R=200px 内邻近关键点的多数类归属选择使用哪个单应（某类占比 <20% 时并入主类）。这一步解决了单一全局单应在**视差场景**下的系统性误差——是 DUT 对传统 MeshFlow 类方法最重要的改进之一。
- **运动细化网络**：以关键点运动 + 相对距离向量为输入的 1D 卷积 + 注意力网络，为每个网格顶点预测在单应初始化基础上的**残差运动**，得到稠密网格运动场。

**③ 轨迹平滑**：把每个网格顶点跨帧串联成轨迹后，用一个 3D CNN 依据轨迹的局部时空上下文**预测逐点动态平滑核与权重 λ**，再用迭代求解器（Jacobi 式）施加平滑。与固定高斯核相比，动态核可以在快速运镜段自动"少平滑"、在抖动段"多平滑"；与传统能量优化（约 100 次迭代）相比，15 次迭代即收敛。

**④ 渲染**：平滑前后网格顶点位置差 `v̂ = v + T̂ − T` 定义每个网格单元的单应，反向 warp + 双线性插值输出，最后统一裁剪。

### 2.3 无监督损失（核心贡献）

**运动细化损失 L_MR**（权重 λ_m/λ_v/λ_s = 10/40/40）：
1. *顶点-关键点运动一致性*：网格顶点运动应与邻近关键点运动的 L1 距离小；
2. *关键点投影一致性*：由网格导出的单应应能把关键点 + 其运动正确投影；
3. *保形约束*：相邻网格边经 90° 旋转关系约束网格保持近矩形，防止扭曲。

**轨迹平滑损失 L_TS**（λ/λ_s/λ_c = 15/40/20）：
1. *时域平滑*：局部时间窗内运动差分最小化；
2. *距离保持*：平滑轨迹不能偏离原轨迹太远（控制裁剪率）；
3. *空间保形*：warp 后网格形状约束；
4. *内容保持*：关键点相对网格的位置关系保持。

> 这套"**运动一致性 + 投影一致性 + 保形 + 时域平滑**"的自监督配方成为后续所有无监督防抖工作（包括 NLNL）的模板。

### 2.4 性能与结果

- **效率**：0.63M 参数（StabNet 为 30.39M），30.42G FLOPs，480p 下 **71ms/帧**（≈14 FPS，GPU）。
- **NUS 基准**（越高越好）：

| 指标 | DUT | StabNet | DIFRINT | MeshFlow | Subspace |
|---|---|---|---|---|---|
| Stability | **0.833** | 0.790 | 0.819 | 0.810 | 0.789 |
| Distortion | **0.949** | 0.672 | 0.853 | 0.779 | 0.900 |
| Cropping | 0.704 | 0.493 | **0.862** | 0.548 | 0.639 |

- 稳定度与畸变全面领先当时的监督方法与传统方法；裁剪率低于 DIFRINT 是 warp 类方法的固有代价（DIFRINT 是插帧式全帧方法）。
- 消融验证：运动细化把单应距离从 0.069 降到 0.043、畸变分从 0.941 提到 0.956；动态核平滑 15 次迭代优于传统优化 100 次迭代（畸变 0.894 vs 0.878）；对光流噪声（5–20% 高斯/椒盐）有较好容忍度。

### 2.5 优点与局限（落地视角）

**优点**：无需成对数据；模型极小（0.63M）；管线各级可解释、可单独替换；多单应对视差场景鲁棒性明显好于单单应/纯网格方法。

**局限**：
1. **离线方法**：轨迹平滑需要完整（或长窗口双向）轨迹，无法零延迟在线运行；
2. **鲁棒性上限受制于运动估计前端**：RFNet + PWC-Net 在弱纹理、低光、红外、大动态前景下会失效，且这两个组件本身较老；
3. K-means 两平面假设与 20% 合并阈值需**逐场景调参**，复杂多平面场景可能引入畸变（作者自述部分视频需要重调阈值）；
4. warp + 裁剪范式导致裁剪率偏低（0.704），全帧需另接补全模块。

## 3. "No Labels, No Look-Ahead"（CVPR 2026）详细解读

### 3.1 动机

作者对现有方法的批评点直指落地痛点：
- 经典方法的手工关键点在弱纹理/遮挡/大运动下失效；学习方法鲁棒但不可解释、不可控；
- 固定平滑策略欠泛化，学习式平滑又易过平滑/畸变；
- **绝大多数方法（点名 DUT）是离线的**，受网络结构与全局平滑策略约束，且依赖的运动估计器不开源、复杂场景鲁棒性差；
- 现有研究几乎只覆盖"手持 + 前视 + 可见光"，无人机、红外、夜间等场景无人评测。

### 3.2 方法：经典三阶段管线 + 极轻量神经残差 + 系统级流水线

**Stage 1 运动估计——多检测器协同**：
- 融合异构检测器（传统 SIFT/ORB + 深度 SuperPoint/ALIKE）输出，加权 NMS 合并；
- **空间选择性聚类**强制关键点在网格上均匀分布（避免纹理聚集导致的传播偏差）；
- 稠密光流用 **MemFlow（因果、带记忆的在线光流）**，并在关键点邻域内用光流、邻域外用关键点插值做加权融合，得到"稀疏引导的因果流"。

**Stage 2 运动传播——EfficientMotionPro（~23K 参数）**：
- **多网格单应先验**：K-means 聚 K 类 + 逐类 RANSAC 单应 + 对网格顶点做**软融合加权**（对比 DUT 的硬多数投票归属）；
- Ghost 模块 + ECA 注意力的残差网络在单应基底上预测逐顶点残差；复杂度 O(5N·C²)，C=48。

**Stage 3 运动补偿——OnlineSmoother（~3.6K 参数）**：
- **因果核平滑器**：左填充卷积编码历史，为 x/y 方向输出可学习的 **3 抽头因果核**（有效窗口 L=7 帧），公式形如 `S_t = (λ·Σ k_r·S_{t−r} + O_t) / (1 + λ·Σ|k_r|)` ——只用过去帧，**零未来帧、零前瞻**；
- Lite LS-3D 编码器 + Star-gated 解码器。

**系统级：三守护线程流水线**（运动估计 / 传播 / 补偿各一线程，有界 FIFO 队列衔接），延迟从三阶段之和降为最慢阶段耗时。**Jetson AGX Orin 上 78.94 ms/帧 ≈ 12.7 FPS**（同平台 MeshFlow 169ms、StabNet 180ms、NNDVS 340ms）。

### 3.3 无监督损失

与 DUT 同源但因果化/自适应化：
- 传播端：关键点一致性（Charbonnier 形式）、单应投影一致性、网格正交保形——三项与 DUT 的 L_MR 一一对应；
- 平滑端：**运动自适应二阶时域惩罚**（按运动幅度衰减权重，抑制加速度）、**DFT 频域高频抑制**（因果窗内）、三角形边长/角度保持的空间畸变约束、关键点投影一致性。
- 训练：自采不稳定视频，EfficientMotionPro 100 epoch（RTX 4090 约 12 小时），OnlineSmoother batch=1 保持因果性（约 2.5 小时）。

### 3.4 UAV-Test 数据集（新基准）

92 段 / 约 26 分钟，**可见光 74 段 + 长波红外（8–14μm）18 段**，DJI M300 RTK + H20N 采集，720p/1080p @25–30FPS，覆盖城市、高速、林山、水岸、工业五类场景（3–5 级风）。首个支持**夜间/红外**评测的防抖基准。

### 3.5 结果

| 数据集 | NLNL（在线） | 最强在线基线 NNDVS | DUT（离线） | RStab（离线 SOTA） |
|---|---|---|---|---|
| NUS（C/D/S） | 0.95 / 0.98 / **0.90** | 0.92 / 0.98 / 0.87 | 0.98 / 0.88 / 0.85 | 1.00 / 0.99 / 0.94 |
| DeepStab | 0.94 / 0.91 / 0.85 | 0.93 / 0.91 / 0.84 | – | – |
| Selfie（剧烈手抖） | 0.98 / 0.93 / 0.91 | 0.97 / 0.92 / 0.91 | – | – |
| UAV-Test | 0.94 / 0.90 / **0.89** | 0.89 / 0.87 / 0.84 | – | 1.00 / 0.96 / 0.94 |

在线方法中全面第一，稳定度上**超过了离线的 DUT**，与离线 SOTA RStab 差距缩小到可接受范围（而 RStab 是重型体渲染方法，不可能在线跑）。

> 注意：不同论文对同一方法的复评分数常有出入（DUT 原文 NUS Stability 0.833，NLNL 复评为 0.85、Cropping 0.98），因为评测实现、裁剪策略与视频子集不完全一致——横向比较应以同一篇论文内部的数字为准。

**消融要点**：去掉多单应 → 抖动上升；去掉关键点协同 → 采样不均导致畸变上升；因果窗 L=7 是稳定性/保真度最优折中（L=5 更稳但失真，L=9 无增益）。

### 3.6 局限（作者自述）

极端视差或大面积动态前景下退化；红外模态依赖足够热对比度；单应先验假设平面主导运动，复杂 3D 平移场景受限；在更低端嵌入式设备上仍可能不够实时。

## 4. 逐维度对比

| 维度 | DUT（TIP 2022） | NLNL（CVPR 2026） |
|---|---|---|
| **任务设定** | 离线（需完整/长窗轨迹） | **在线、零未来帧**（严格因果，只用 I_{t−1}, I_t） |
| **延迟** | 整段视频级 | 单帧级（最慢流水线阶段 ≈ 79ms） |
| **运动估计前端** | RFNet 关键点 + PWC-Net 光流（单一来源，弱纹理/红外易失效） | SIFT/ORB/SuperPoint/ALIKE **多检测器协同** + 均匀化 + MemFlow 因果流融合 |
| **稀疏→稠密传播** | K-means 两平面多单应（硬归属）+ 残差细化网络 | K 类多单应**软融合** + Ghost/ECA 残差网络（~23K 参数） |
| **轨迹平滑** | 3D CNN 预测**双向**动态核，迭代求解（需要未来帧） | **因果 3 抽头动态核**（L=7 历史窗）+ 频域高频抑制 |
| **无监督损失** | 关键点/顶点一致性 + 单应投影 + 保形 + 时域平滑（模板首创） | 同一配方的因果化升级：+ 运动自适应二阶惩罚 + DFT 频域项 |
| **参数量** | 0.63M | **~27K（23K+3.6K）**，小两个数量级 |
| **实测速度** | 71ms/帧 @480p（桌面 GPU） | 78.94ms/帧（**Jetson AGX Orin 嵌入式**） |
| **系统工程** | 无 | 三线程流水线 + 有界队列，延迟=最慢阶段 |
| **评测场景** | NUS（手持可见光） | NUS/DeepStab/Selfie/GyRo + 自建 **UAV-Test（无人机+红外+夜间）** |
| **鲁棒性策略** | 多单应处理视差；对光流噪声有容忍 | 前端冗余（多检测器）、分布均匀化、软融合、自适应平滑——**系统性防失效设计** |
| **共同局限** | 大动态前景、极端视差下退化；warp+裁剪范式，非全帧 | 同左（单应/网格先验的共同天花板） |

## 5. 关系解读与落地启示

**继承关系**：NLNL 在框架层面完全是 DUT 范式——"经典管线骨架 + 每级神经化 + 时空一致性自监督"。它的每一项改动都精准对着 DUT 的一个落地短板：

1. DUT 离线双向平滑 → 因果动态核 + 流水线，解决**在线性**；
2. DUT 单一前端（RFNet/PWC-Net）→ 多检测器协同 + 因果光流融合，解决**前端鲁棒性**（这正是 DUT 在低光/红外/弱纹理下失效的根源）；
3. DUT 硬聚类归属 + 手调阈值 → 软融合加权，降低**逐场景调参**负担；
4. 0.63M → 27K 参数 + Jetson 实测，解决**嵌入式部署**。

**对本项目（VideoStab）的启示**：
- 若目标是**在线/嵌入式纯视觉防抖**，NLNL 的架构是当前最佳参考蓝图；即使不复现全部，"多检测器关键点协同 + 网格软融合多单应 + 因果动态核平滑"三件套可以逐个移植到现有管线；
- 若目标是**离线后期**，DUT 官方代码（PyTorch，含 RFNet/PWC-Net 权重）仍是无监督路线里最易上手的起点，但建议把前端换成现代组件（如 ALIKE/SuperPoint + RAFT/MemFlow）——这基本就是朝 NLNL 方向演化；
- 两者共同的天花板是 **2D 网格 + 单应先验**：大视差、大动态前景仍会退化，且都非全帧（需裁剪）。若这两点是硬需求，需往全帧补全（Fast Full-frame ICCV'23）或 3D 路线（RStab/GaVS）叠加，代价是失去在线性;
- 复现评测时注意：C/D/S 三指标跨论文不可直接比对，务必在自己的评测框架内统一重跑基线。

## 6. 以 DUT 为基准的复现实验记录（2026-07）

在 DeepStab 上实际训练后，本仓库两个网络最初**都不如经典 fallback**。以 DUT
原文公式为基准逐项对照，定位并修复了 7 个实质缺陷，每个都有数值证据。

### 6.1 修复清单

| # | 缺陷 | 证据 | 修复 |
|---|---|---|---|
| 1 | 保形项零填充 bug | 零畸变的常数场被罚 0.876（修正后 0.001），污染 27% 边界顶点，且占总损失 64% | replicate padding |
| 2 | 保形项选错约束 | 剪切(真畸变) 0.4436 vs 平移(零畸变) 0.4384，几乎无法区分 | 换 DUT R90 矩形保持 |
| 3 | 通道注意力 ≠ 关键点注意力 | ECA 原理上无法在关键点间选择，丢失 DUT 的离群点鲁棒机制 | 换点云式关键点注意力 |
| 4 | 平滑器无数据锚 | 纯卷积 P←K*P 无不动点，平滑量随迭代无界发散(0.043→0.0003) | 换 DUT Jacobi 数据锚式 |
| 5 | 数据保真项权重过重 | 量级达 45，完全主导损失并推向"不平滑"退化解 | 权重经对齐扫描标定为 0.01 |
| 6 | 频域项方向相反 | 罚完美平滑的线性漂移 64.6，罚真实抖动仅 1.29（50 倍反向） | 移除 |
| 7 | 求解器触达不足 | ±3 抽头 ×15 迭代等效 σ 仅 6.7 帧，够不到强平滑区 | 膨胀(Fibonacci)抽头，触达 ±21 |

### 6.2 最关键的方法论：损失-渲染对齐扫描

前三次训练全部崩向"不平滑"，我曾先后归因于损失配平、架构起点，均被证伪。
决定性诊断是**固定 w、扫描 λ，同时记录损失与真实渲染质量**：

| λ | 总损失 | 渲染 rough |
|---|---|---|
| 0.05 | **2.20**（最优） | 0.3734（最差） |
| 200 | 46.64（最差） | **0.0639**（最优） |

损失最优点与渲染最优点**完全反向**。这一步一次性暴露了缺陷 5/6，并避免了
在错误目标函数上继续消耗算力。**任何无监督训练开工前都应先做这个验证。**

### 6.4.2 校正场各向异性封顶（Zooming distortion 短板的解法）

> 本节所有数字为 **proxy_height=360** 口径，与 6.4 表（480）不可直接混用。

**根因。** 相机路径按**逐顶点平移**累积、并**逐顶点独立**平滑。平移主导场景下
各顶点运动几乎相同，独立平滑无害；但缩放/前进类运镜下顶点沿半径以不同速率
运动，独立平滑后相位不再协调，合成的校正场 B **不再是一个合法的相似变换**，
网格被剪切拉伸。实测 B 的非相似占比：Zooming 23~32% vs Regular 6%。

**解法。** 把 B 最小二乘分解为「相似变换拟合 + 残差」，对残差幅值封顶
（`SmoothingConfig.anisotropy_cap_ratio`，默认 5/360 ≈ 360p 下 5px）。

**τ 扫描（NUS 全量 144 段，full 配置）：**

| τ | distortion | rough | 收益/代价比 |
|---|---|---|---|
| 不处理 | 0.8679 | 0.5795 | — |
| 1px | 0.9641 (+11.1%) | 0.6856 (+18.3%) | 0.60 |
| 2px | 0.9432 (+8.7%) | 0.6282 (+8.4%) | 1.03 |
| 3px | 0.9245 (+6.5%) | 0.6020 (+3.9%) | 1.67 |
| **5px（默认）** | **0.9033 (+4.1%)** | **0.5812 (+0.3%)** | **14.4** |

选 5px 因为它是唯一**统计上免费**的工作点：配对符号检验 distortion
117/144 段改善（z=+7.50，显著），rough 65/79（z=−1.17，与噪声无异），
stability 持平。需要更高画质且能接受 stability 代价时可收紧到 3px。

**Zooming 类是双赢**（印证机制判断）：distortion 0.796→0.870 的同时
rough 也从 0.628 降到 0.551。聚合 rough 的那点代价全部来自 Parallax 与
Running——那里的残差是真实视差信号。

**出厂配置下两个网络的净贡献**（classic+5px → full+5px）：

| 配置 | distortion | rough | stability |
|---|---|---|---|
| classic 无封顶 | 0.8789 | 0.7361 | 0.9264 |
| classic + 5px | 0.9104 | 0.7162 | 0.9272 |
| full 无封顶 | 0.8679 | 0.5795 | 0.9289 |
| **full + 5px（出厂）** | 0.9033 | 0.5812 | 0.9299 |

网络 rough 增益 **−18.9%，137/144 段改善（z=+10.83）**，逐类别全部为正
（Regular −29.8% / Crowd −28.9% / Parallax −23.2% / Running −19.9% /
Zooming −17.5% / QuickRotation −6.3%）。

**对 classic 基线封顶是纯双赢**：distortion +3.6% 的同时 rough 也改善 2.7%。

**对 6.5 的部分缓解（注意不是根除）。** 传播网的 distortion 代价：
无封顶 −0.0109 → 出厂 5px 下 **−0.0071**（减少约 35%）。

> ⚠️ 一处已更正的错误结论：曾记为"封顶后代价归零到 −0.0000"。该测量是在
> **τ=1px** 下做的（紧封顶几乎削光了网络产生的各向异性，故代价归零），
> 但被误写成对出厂配置的论断。**出厂 τ=5px 是松封顶，代价仍有 −0.0071。**
> 6.5 提出的"训练回路内加入与封顶对齐的各向异性约束"因此依然是有效方向。

**三条被实验推翻的直觉（勿再重走）：**

| 假设 | 结果 |
|---|---|
| 逐顶点自适应 sigma 破坏相似性，改均匀 sigma 可解 | **反向**：均匀 sigma 让 distortion 更差 |
| 有害各向异性是逐顶点噪声，空间低通可滤 | **证伪**：σ=0.8/1.5 只换来 +1.0~1.7%（限幅同条件 +7.2%）。它是**大尺度低频剪切**，空间上本就平滑 |
| 缩样足以定工作点 | **证伪两次**：9 段子集显示"三指标全赢"，全量未复现；36 段子集又低估收益（Zooming 基线 0.906 vs 全量 0.796） |

### 6.4.3 裁剪预算是不是 rough 的瓶颈？（P4，结论：只对 Running 是）

**先修正一个误导性的比较。** 曾以"Running 0.865 / Parallax 0.816 是 Regular
0.149 的 5.5 倍"提出问题，但它们**输入本就抖 1.9 倍**。按 rough 降幅重排：

| 类别 | 预算饱和率 | rough 降幅 |
|---|---|---|
| Regular | 22% | **90%** |
| Running | 100% | 71% |
| Parallax | 44% | 68% |
| Zooming | 86% | 66% |
| Crowd | 91% | 65% |
| QuickRotation | 97% | **39%** |

Running/Parallax 与 Crowd/Zooming 同档，真正的异类是 QuickRotation。

**预算扫描（NUS 144 段，full+封顶5px）：**

| crop | distortion | rough | cropping |
|---|---|---|---|
| **0.12（出厂）** | **0.9033** | 0.5812 | 0.8810 |
| 0.20 | 0.8420 | 0.5491 | 0.8025 |
| 0.30 | 0.5156 | 0.6073 | 0.7049 |

逐类别 rough 只有 **Running（饱和率 100%）随预算放宽而显著改善**
（0.865→0.647，−25%），其余类别**反而变差**。

**结论：**
1. **饱和 ≠ 受限。** 109 段饱和视频中仅 51 段受益（平均 +3.3%）；
   QuickRotation 饱和率 97% 却普遍受损。撞上限不代表瓶颈在上限。
2. **Running 是真受限且几乎免费**：改善最大的 10 段全是 Running，
   rough +30~40%，distortion 代价约 1%。当前单项最大可得收益。
3. **大预算普遍有害**是 6.4.2 机制的延续（|B| 越大各向异性越大）。

> ⚠️ 本条曾写作"crop=0.30 时残差占比已被压到 5%，distortion 仍崩到
> 0.5156，存在封顶之外的第二种失效"。**两处均已被 6.4.4 推翻**：
> 残差占比实测是 12~20%（"5%"是未测就写的推算）；而 0.5156 里含大量
> **指标伪影**——crop=0.30 下 distortion 的量程上限只有 0.919。
> 按上限归一化后为 0.908 → 0.849 → 0.561，大预算有害的**方向成立**，
> 但幅度被显著夸大，也不需要引入"第二种失效"来解释。

**可落地方案与其缺口：** 用"事后知道哪些段受益"的预言机估上界，rough
0.5812→0.5298（−8.8%），但 distortion 0.9033→0.8657、cropping 0.881→0.853。
该结果**用了结果信息，不可直接实现**。可实现规则需要事前预测器，而饱和率
本身太弱（51/109）。更有希望的信号是**钳位前 |P−C| 的分位数与预算上限之比**
（管线内现成可得，但尚未埋点）。**在预测器验证前不应上自适应预算**，否则
只是调参。

### 6.4.4 预算钳位本身就是各向异性的来源（P8）

追查"大预算下的第二种失效"时发现了两件事，都推翻了先前的记述。

**一、distortion 指标在大裁剪比下失准**（详见《评测指标说明》§2.2）。
crop=0.30 时指标上限只有 0.919，crop=0.40 时崩到 0.178。6.4.3 观察到的
"崩到 0.5156"里含大量伪影。出厂 crop=0.12 偏差仅 0.5%，不影响已有结论。

**二、裁剪预算的逐顶点钳位会生成各向异性。** 这解释了一个反直觉的实测：
**预算越紧，残差反而越大**（Zooming/16 残差最差帧：crop 0.12 下 13.85px
vs crop 0.30 下 7.65px），尽管封顶值恒为 5px。

机理：当需要的校正远超预算盒时，逐顶点分量级 clip 会把不同顶点削去
**不同的量**，而"削去不同的量"本身就是剪切。因此 `limit_anisotropy` 里
"削残差 → 钳预算"的顺序会让钳位把刚压下去的各向异性重新引入。

改为**交替投影**（两个约束集——残差范数 ≤ τ、预算盒——都是凸的，故收敛）。
但要注意其上限：当两约束不相容时，投影收敛到折中而非 τ。合成极端场上
从 14.5px 收敛到 12.9px（够不到 5px 的目标），真实数据上收益集中于
预算被顶死的样本：

| 视频 | iters=1 | iters=4 | 改善 |
|---|---|---|---|
| Zooming/16 | 13.85 | 11.61 | 16.2% |
| Parallax/0 | 5.30 | 5.00 | 5.6% |
| Zooming/10 | 6.02 | 5.87 | 2.5% |
| Running/11 | 7.58 | 7.52 | 0.8% |
| Regular/0 | 4.18 | 4.18 | 0% |

**端到端 A/B（36 段分层子集，iters=1 vs 4）：三项指标全落在噪声内。**

| 指标 | iters=1 | iters=4 | 改善/恶化 | 符号检验 z |
|---|---|---|---|---|
| distortion | 0.9201 | 0.9217 | 19/17 | +0.33 |
| rough | 0.4739 | 0.4784 | 18/18 | 0.00 |
| stability | 0.9291 | 0.9283 | 20/16 | +0.67 |

**故默认保持 iters=1。** 残差指标上"理论更对"没有兑现成端到端收益，
不以理论正确为由保留多余迭代（参数保留以便复查）。

**结论：这不是可以"修掉"的 bug，而是预算硬约束与相似性保持之间的固有
张力**——校正需求远超预算盒时，逐顶点 clip 必然把不同顶点削去不同的量。

### 6.4.5 保相似结构的预算投影（P9）：已实测否决

6.4.4 曾提出"让预算投影本身保持相似结构"作为真正的解法。**已实现并否决。**

做法：逐帧求整体等比缩放系数 s_t 使 |B| 落入预算盒（缩放一个相似位移场
D = M·v + b 得 s·D = (sM)·v + sb，仍是合法相似场，故结构**精确**保持，
实测残差 ~1e-6）；s_t 逐帧跳变会引入新抖动，故取滑动最小下包络再平滑、
并与原值取小（保证只降不升，约束不被破坏）。

**36 段分层子集 A/B：**

| 方案 | distortion | rough | stability |
|---|---|---|---|
| **钳位+封顶（出厂）** | **0.9225** | **0.4809** | 0.9285 |
| 相似缩放 | 0.9093 (z=−1.33) | 0.5263 (**z=−2.33**) | 0.9254 |
| 相似缩放+封顶 | 0.9217 (z=+0.33) | 0.5372 (**z=−2.00**) | 0.9239 |

**失败是结构性的，不是参数问题。** 钳位只削超标顶点，缩放衰减**所有**
顶点；预算顶得越死缩放系数越小，恰好在最需要校正处削得最多。Running
（饱和率 100%）最能说明：distortion 确实从 0.8896 提到 0.9186（保结构
有效），但同处 rough 从 0.9158 崩到 1.1146（−22%）。

**结论：逐顶点钳位造成的剪切，代价小于均匀衰减损失的校正幅度。
"预算投影"方向就此关闭**，实现代码已移除（本节保留足以重建的细节）。

### 6.4.6 产品三档位的标定（P10/P11）

需求：给出「裁切最小 / 推荐 / 最稳定」三档，日常默认推荐档。

三档本质是同一权衡——**裁掉多少画幅 ↔ 换来多稳**——上的三个工作点，故以
`crop_ratio` 为主轴。**注意 6.4.3 已证大预算并非单调更好，所以最稳定档
不能想当然取大值，必须实测找拐点**；又因 distortion 随裁剪比失准
（6.4.4），跨档位比较前先测了各档的指标量程上限用于归一化。

**主轴扫描（NUS 144 段全量，full + 封顶 5px，proxy 360）：**

| crop | cropping | distortion | 归一化 | rough | stability |
|---|---|---|---|---|---|
| 0.06 | 0.9400 | 0.9122 | 0.9143 | 0.8109 | 0.9220 |
| 0.08 | 0.9211 | 0.9077 | 0.9118 | 0.7023 | 0.9265 |
| **0.12** | 0.8810 | 0.9033 | 0.9083 | 0.5812 | 0.9299 |
| 0.16 | 0.8417 | 0.8905 | 0.8978 | **0.5474** | 0.9308 |
| 0.20 | 0.8025 | 0.8420 | 0.8555 | 0.5491 | 0.9299 |
| 0.30 | 0.7049 | 0.5156 | 0.5611 | 0.6073 | 0.9277 |

**相邻档位配对符号检验把拐点精确定位在 0.12：**

```
0.06→0.08  rough 136/144 z=+10.67 ✅   distortion z=−0.17（无代价）
0.08→0.12  rough 125/144 z= +8.83 ✅   distortion z=−1.67（无显著代价）
0.12→0.16  rough  77/144 z= +0.83 ✗    distortion z=−2.33 ⚠️
```

拐点前每一档都是「rough 大赢 + distortion 零代价」，越过 0.12 后 rough
收益立刻掉进噪声而 distortion 开始显著恶化。**历史出厂值 0.12 恰在拐点上。**

**rough 全局最小值在 0.16 而非 0.12，但分类别才看得懂原因：**

| 类别 | 0.12 | 0.16 | |
|---|---|---|---|
| Running | 0.8646 | **0.6833** | −21% |
| Zooming | 0.5512 | 0.5162 | −6% |
| Crowd | 0.4348 | 0.4564 | +5% |
| Regular | 0.1489 | 0.1508 | +1% |

难场景大赢、易场景小输，互相抵消——正是 6.4.3「只有 Running 真正受预算
限制」的独立复现。

**τ 副轴：大预算档必须收紧封顶。** 0.16 档 distortion 显著劣于推荐档
（z=−2.33），而 6.4.3 已证各向异性随 |B| 增长，故在 crop=0.16 上扫 τ：

| τ | 归一化 distortion | rough | vs τ=5px |
|---|---|---|---|
| 3px | 0.9266 | 0.5717 | distortion z=+8.50 / rough z=−3.67 |
| **4px** | **0.9071** | **0.5543** | distortion z=+5.33 / rough z=−2.00 |
| 5px | 0.8978 | 0.5474 | 基准 |

τ=4px 把 distortion 追平推荐档的 0.9083（差 0.13%），同时 rough 仍优于
推荐档；τ=3px 收得过头，rough 退回 0.5717。**故最稳定档 = crop 0.16 + τ 4px。**

**最终三档**（见 `config.PRESETS`）：

| 档位 | crop | τ | cropping | rough | 归一化 distortion |
|---|---|---|---|---|---|
| minimal_crop | 0.08 | 5px | 0.921 | 0.702 | 0.912 |
| **recommended** | 0.12 | 5px | 0.881 | 0.581 | 0.908 |
| most_stable | 0.16 | 4px | 0.842 | 0.554 | 0.907 |

**裁切最小档取 0.08 而非 0.06**：0.06→0.08 是整条曲线性价比最高的一步
（136/144 段改善，z=+10.67，distortion 零代价），只多裁 1.9 个百分点画幅
却换来 rough 改善 13%。为 2 个点的画幅让防抖档在本职工作上差 13% 不划算。

> ⚠️ **most_stable 并非全局更稳，务必如实标注。** 相对推荐档的 rough
> 配对符号检验 z=+0.33（不显著）。144 段中 74 段改善（均值 −0.0795px）对
> 70 段变差（均值 +0.0287px）——赢的幅度是输的 2.8 倍，净 −0.0269px/段，
> 但**赢面高度集中在 Running/Zooming**。它是高动态素材的专用选项，
> 不是"更好的推荐档"。

### 6.4.7 角点空间改造(M1–M5):果冻的结构性根除

**起因**:用户在真实素材(data/test,4K/1080p 手持)上报告**持续性果冻**
——"一根直的杆子一直是扭曲的,不同地方强弱不一样"。此前的时间尖峰诊断
(P17–P22)方向全错;换成"直线弯曲量"度量后一次定位。

**病因归因**(18 段,`bend_px` = 网格行/列共线性残差):

| 配置 | 弯曲 p50 | 恒定分量 |
|---|---|---|
| classic(无网络) | 1.16px | 0.21 |
| +传播网 | 2.62px | 0.22 |
| +平滑网 | 1.81px | **0.37** |
| full(出厂) | **2.84px** | 0.38 |

传播网贡献弯曲幅度(翻倍),平滑网贡献"持续"性(恒定分量 +76%);
网格模型本身有 1.16px 基线。τ 收紧到 1px 恰好抵消网络份额,但用户
确认 τ=1px 仍有可见果冻 → 必须结构性解决。

**方案**(借鉴工程界四角点方法,详见 `smoothing/corner.py`):每帧运动
投影到全局单应子空间,只取 4 角点位移(8 维),平滑与预算投影全在 8 维
进行,逐帧 4 点恰定单应反解稠密场。输出恒为单应位移 ⇒ **弯曲数学上为零**。
`accumulate/gaussian/budget` 三件套对网格形状无假设,原实现零改动复用;
预算在角点钳住即全帧成立,逐顶点钳位(6.4.4 的固有张力)整体消失。

**NUS 144 段最终 A/B(proxy 480)**:

| 臂 | rough | 弯曲p95 | distortion | stability |
|---|---|---|---|---|
| vertex_full(旧出厂) | **0.5742** | 5.640 | 0.9019 | 0.9301 |
| vertex_classic | 0.7197 | 3.806 | 0.9114 | 0.9267 |
| corner_classic | 0.7148 | 0.146 | 0.9285 | 0.9251 |
| **corner+网络(新出厂)** | 0.6072 | **0.125** | **0.9303** | 0.9290 |

关键发现与两个负结果:

1. **顶点自由度对 rough 贡献为零**:corner_classic vs vertex_classic
   z=+0.83 无差别。旧出厂领先的 24.5% 全部来自网络的平滑策略。
2. **角点模式直接复用顶点训练的 smoother.pt(零样本)**。为角点重训
   (z=−5.50)与微调(z=−2.00)均显著更差:角点窗口只含 4 条轨迹,
   顶点窗口 192 条,速度统计的丰富度单向泛化。
3. **受限视差残差层已否决**(时间低通+τ帽从顶点解提取慢变非单应分量):
   Parallax+Crowd 41 段 rough 收复不显著(z=+1.09),弯曲却弹回 3.3px,
   distortion 显著变差(z=−5.15)。顶点网络的视差优势来自逐区域平滑
   过程本身的自由度,事后分离拿不回。代码已移除。

**代价与定位**:全局 rough +5.7%,视差类 +20~25%(Parallax 1.02 vs
0.82、Crowd 0.54 vs 0.43);Running/Zooming/QuickRotation 三类反超旧
出厂。在"极度厌恶果冻"的产品要求下,这是正确的工作点;真实素材上
弯曲 p95 从 ~3px(τ=1px 仍可见)降到 ~0.1px 量级,用户确认可见改善。

### 6.5 传播网络仍未根除的问题

修复 8+9 把 R90 非矩形度的退化压低了约 30~40%（3.avi 由 +293% 降到 +187%），
但**没有根除**——即便加了抗离群点的中位数项和 10 倍保形权重，网络仍倾向用
网格形变去贴合含噪的关键点观测。这说明该权衡是**结构性**的。可能的下一步：
- 用跟踪置信度（前后向误差/RANSAC 内点距离）对关键点加权，让网络天然轻视
  不可靠观测；
- 在损失中显式惩罚残差场的局部方差（而非仅网格非矩形度）。

### 6.6 与 DUT 的比较：能说什么，不能说什么

**不能**直接对比 DUT 论文报告值（Stability 0.833 / Distortion 0.949 /
Cropping 0.704）：那是 NUS 数据集 + 其自有指标实现，本节是 DeepStab + 本仓库
实现。跨论文 C/D/S 数字不可比对。要做对等比较需在同一批视频、同一套指标下
跑 DUT 官方代码（[DUTCode](https://github.com/Annbless/DUTCode)），属独立工作。

**可以**主张的是架构层面的、不依赖指标口径的差异：
1. **裁剪预算硬约束**：稳定输出 0.88；DUT 无预算概念，其论文报告 cropping
   0.704（丢失近 30% 画面）。这是设计差异，不是测量差异。
2. **自适应 K + 软融合**（DUT 固定 2 平面 + 硬归属 + 手调 20% 阈值，作者
   自述需逐场景调参）。
3. **预算感知 λ**：把"参考平滑相对预算的余量"输入网络，使 λ 在余量充足处
   放开、逼近边界时收敛——DUT 无此机制。
4. **膨胀时间抽头**：14 抽头触达 ±21（DUT 连续抽头 ±6），等效 σ 约 39 帧。
5. 三级失效降级、转场切分、透视分量守门（DUT 均无）。

### 6.7 仍未解决（修正指标后依然成立的真问题）

1. ~~**Zooming 类 distortion 明显偏低**~~——**已解决，见 6.4.2**。根因不是
   "单应+网格模型吃力"，而是逐顶点独立平滑破坏了校正场的相似变换结构；
   对残差各向异性封顶后 Zooming distortion 0.796→0.870 且 rough 同向改善。
2. **守门机制几乎不触发**：144 段真实难例上 L1 仅 0.2–0.4%、L2 全零，说明
   阈值比数据的最坏情况还松。这套"产品鲁棒性核心"至今未被验证，需要低光/
   弱纹理素材（NUS 六类均为正常光照）。
3. **传播网的 distortion 退化未根除**（见 §6.5），且在 NUS 上仍存在
   （0.862 → 0.845）。
4. **多单应机制价值有限**：真实视差是深度连续分布，实测 err(K=2)/err(K=1)
   中位数 0.993，一半帧对上分平面毫无改善。

### 6.8 前端选型：ALIKED 不采用（640 帧对隔离测量）

| 组合 | 点数 | 成活率 | 单应残差(±std) | 覆盖率 | 耗时 |
|---|---|---|---|---|---|
| orb | 170 | 0.994 | 0.191 ±0.116 | 0.369 | — |
| gftt | 398 | 0.974 | 0.280 ±0.165 | 0.787 | — |
| aliked | 301 | 0.961 | 0.277 ±0.181 | 0.563 | 2.5× |
| **orb_gftt**（采用） | 428 | 0.976 | 0.275 ±0.161 | 0.790 | 16 ms |
| orb_gftt_aliked | 501 | 0.967 | 0.289 ±0.172 | 0.831 | — |

- **精度与覆盖率互斥**：ORB 残差最低但覆盖仅 0.369，加入任何检测器都会把
  残差推到 0.275–0.290；
- ALIKED 与 GFTT 残差**统计上无法区分**（0.277 vs 0.280，std 达 0.17），
  但覆盖率明显更差且贵 2.5 倍；
- **ALIKED 配描述子匹配更差**：互近邻匹配残差 0.560 vs LK 0.131。相邻帧
  基线极小，描述子的视角不变性用不上（余弦相似度全挤在 0.988–1.0），而
  匹配精度受两帧关键点定位的双重限制，LK 则以首帧为锚做亚像素细化；
- **"高精度点拟合全局模型"的分层设想被证伪**：留出集评估下 ORB 只在 32.9%
  的帧胜出。此前"ORB 精度最高"是 **in-sample 残差**的假象——ORB 点空间聚集，
  单应在那一小片拟合得好但外推能力差（Parallax 上留出残差 0.654 vs GFTT 0.416）。

前端误差(fb_err ~0.006px)在总误差预算中占比 <4%，模型误差(~0.16px)大 27 倍，
这也是换检测器/换光流(RAFT)都动不了端到端指标的根本原因。
